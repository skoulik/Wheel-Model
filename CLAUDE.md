# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Repository Is

A quantitative finance modeling project: a mathematical model of the "wheel" options strategy (selling cash-secured puts, taking assignment, selling covered calls until called away), framed as a stochastic inventory system. The end product is a **LaTeX article for a general audience** describing the model in full. Supplementary artifacts (simulators, verification code) are added on a per-need basis.

## Repository Layout

- `sections/` — the article, one `.md` file per section, numbered in reading order. `sections/00-notation.md` is the **single source of truth for all symbols and conventions**; update it whenever a symbol is introduced or changed.
- `code/` — all scripts. `code/verify_examples.py` recomputes every worked numerical example quoted in the sections. **Run it after touching any formula or example**: `python code/verify_examples.py` (~13 min, measured 2026-11-24 on the Windows desktop; `--full` adds the stationary figures). When adding a worked example to the text, add a corresponding check. It ends with the apparatus checks — reproducibility coverage, citations, §00's anchor registers, derivations, figures and the appendix — each also available alone as `python -m examples --coverage` / `--references` / `--registers` / `--derivations` / `--figures-check` / `--appendix-check`. The reproduction appendix `sections/99-reproduction.md` is generated by `python -m examples --appendix` (~20 s) and prints what each command prints rather than what its case asserts, so **any model change makes it stale, not only an assertion change** — regenerate it in the same commit, keeping its CRLF endings; the check fails until you do.
- `figures/` — the article's graphs, as SVG, drawn by the example script that computes their numbers (a `FIGURES` list beside its `FIELDS`), or for a schematic that computes nothing — §02's payoff diagrams — by a figure-only script with no cases. All are styled in one place, `code/figures.py`. Generated, never hand-edited: `python -m examples --figures` redraws them, output is byte-deterministic on any machine (LF line endings on every platform), and `verify_examples.py` fails on a committed figure that no longer matches a fresh draw — so **a model change that moves a plotted number regenerates the figure in the same commit**, like the appendix. A graph replaces a table wherever the table samples a continuous function; converting one means rewriting the prose that read values off the table, not just swapping it (plan: `drafts/2026-09-15-figures-plan.md`).
- `TODO.md` — open modeling/writing issues **only**, grouped by article part and numbered per part (`I-1`, `IV-2`, …); sections would reference them as "TODO IV-2", though none currently does. Resolve an item by fixing the sections, moving it to `DONE.md`, and removing any in-text flag.
- `DONE.md` — completed work, resolved questions, and the four things deliberately descoped, with the map from the old flat `#1`–`#25` numbering that `drafts/` still cites. Entries are never silently edited: a later withdrawal is appended as a dated `**Amended:**` note.
- `drafts/` — historical drafts, named `YYYY-MM-DD-<description>.md`. The initial draft summarizes a prior modeling discussion; it contains a known-wrong P&L formula (see `DONE.md`) — the sections, not the draft, are authoritative. One file there is deliberately undated because it is still growing:
  - `drafts/tranche-record.md` — the live account's statement tranches as they arrive (roughly monthly): what each contained, its regime label, and the headline ledger and spine figures as they stood. **Read it before touching anything in `statements/`** — it holds the ingest command list and the discipline. Rows are append-only and are never recomputed; the window is always everything to date, never a chosen sub-window. It replaced the pre-registration's "wait for six months or twenty lots" trigger, retired in that file's Appendix B on 2026-08-01. Keep it free of dollar amounts: aggregates and percentages only, never account size or exposure.

## Writing Workflow

- Article sections are developed in Markdown, one file per section — not directly in `.tex`. Conversion to LaTeX happens at assembly time.
- Math is written in **Unicode plain text** (τ, σ, N(−d₂)), not LaTeX markup — a deliberate decision for raw readability.
- Cross-section references use pandoc-style anchors: each section H1 is `# Title {#sec:name}`, and prose references are markdown links like `[the holding-time section](#sec:holding)` (they become `\label`/`\ref` at assembly). The anchor list lives in `sections/00-notation.md` Conventions.
- **Citations work the same way and are never numbered by hand.** `sections/98-bibliography.md` is the only file that may declare a `{#ref:...}` anchor; prose cites it as a markdown link (`a correction due to [Siegmund](#ref:siegmund-1979)`), which becomes `\cite{}` and a bracketed number at assembly. Everything after the anchor on an entry line — read level, local PDF name, URL — is internal and stripped at assembly. Read levels **[F]**/**[P]**/**[A]** bind: *never quote a number from an [A] source without opening the paper*. Cite where the reader meets the claim, not only in §03. `python -m examples --references` checks the whole apparatus and runs inside `verify_examples.py`.
- **A claim that rests on another part of the article is signed.** A back-reference, a result restated in §02 or in a closing, a pointer that says what a later section shows: `python -m examples --sign CITING TARGET` fingerprints both sides into `sections/claims.tsv`, and `verify_examples.py` fails when either is reworded. CITING is a section file (its paragraphs that link TARGET) or a `para:` anchor (a paragraph that restates without linking); TARGET must be precise — a formula, a figure, an anchored subsection or a `para:` paragraph anchor (§00's convention) — and a whole section is refused, since its every edit would flag every claim on it. **Re-sign only after rereading the two together**: a signature says someone read both sides, and renewing signatures in a loop certifies nothing. Pointers are not claims and are not signed — except into a section §00 registers but nobody has written: every link there is a **promise**, which `--sign` records as pending, an unregistered one fails, and all of a section's promises fail the day its anchor appears, to be read against what it says. Every other link must land on a declared anchor. Plan: `drafts/2026-10-22-drift-checks-plan.md`.
- Target audience is the general public. Every modeling assumption must be justified in plain terms, not just stated.
- Every parameter gets a proper explanation when first introduced (what it means, typical values, why it matters).
- Before using a mathematical construct, include a short self-contained detour (blockquote style, see existing sections) explaining what it is with a pointer for further reading.
- **A section may point forward; it may not conclude forward.** Stating a later section's *result* where its machinery does not yet exist produces prose that reads fluently and cannot be checked — and the correct version usually already exists downstream, better put. §04 carried four of these at once (2026-08-06, see `DONE.md`): a √tenor premium law where the article has no premium formula at all, a premium-per-contract claim §06 states correctly, "a reason nobody expects" that §07 contradicts with a citation, and 291 words concluding §09's leverage result and §11's barrier. A forward *pointer* is fine and is what the reader wants; a forward *conclusion* is a promissory note. Reader reports do not catch these, because nothing about them confuses a reader.
- **Prose does not defend or vouch for itself.** Two kinds of sentence read as apology to a reader who never saw what they answer, and both go. One argues with a charge nobody has made — "that is not an approximation", "not a modelling artifact", "nothing is being approximated", "exact rather than approximate" — and is usually residue of a correction logged in `DONE.md`, still arguing with a claim the text no longer makes. The other certifies the article's own candour or standing — "honest" as self-description, "stated here rather than buried", "authors with no stake in this conclusion", a credential such as "standard in computer performance analysis" that says nothing about the wheel. Cut it, or state plainly the fact it was wrapping. **Keep** a negation that answers a doubt a reader would really have ("not a coincidence — it is what near-fair option pricing means", "not a paradox"), and the flagging that introduces a disclosed assumption. Sergei set this on §08 and a whole-article sweep removed 33 such sentences (2026-09-15, `159d3fc`); keyword search found under half of them, so check new prose by reading it.
- **A section that closes does so under a heading, and the heading says what it contains.** Not every section needs a closing subsection — §04, §05, §06 and §09 end on their last substantive one, and that is fine — but a recap floating unheaded at the end of the last subsection belongs to *that* subsection, which is how §08's whole-section summary briefly ended up inside "A note on the shape of the distribution" (2026-09-18). The model is §07's **"What this section changed"**: a short recap ending on a one-sentence handoff that names the next section by link. `## Summary` is not a title — it was the only generic heading in the article, and §10 and §11 lost it on the same date. Decide per section as each is worked; do not add closings as a batch.
- Accounting-track discipline: label every P&L/capital formula with its track (A = realized cash, B = market-priced capital, C = opportunity cost). Mixing tracks caused the one substantive error found so far.

## The Model (big picture)

- **Notation:** see `sections/00-notation.md`, which is authoritative. Core symbols: cadence T ≥ tenor τ_p, call period τ_c, n = τ_c/τ_p; p\* the strike dial (a *real-world* assignment probability, from which k\* follows); x = ln(K_c/S) the depth of a lot below its own frozen call strike.
- **The spine.** One state variable and one chain of formulas. Depth is a Gaussian random walk sampled on the call grid, with drift ν = m − σ²/2; a lot exits at the first grid point with x ≤ 0. From that: the entry law for x₀ → the survival sequence → E[W] by first passage → E[I] = λ·E[W] by Little's law → the depth census → income and capital as integrals against the census → the stability criteria.
- **One measure, two worlds.** Every probability is computed at a single price drift m, and a "measure" is a value of m: m = μ − δ (real world, leads) or m = r − δ (what option prices imply, reported alongside). Premiums are never derived from either — they are quotes, priced at σ_IV, which defaults to σ (no volatility risk premium assumed).
- **The running example** is the live account's rhythm: a put sold every week (T = τ_p = 1/52) and calls written for four weeks (n = 4, τ_c = 1/13), p\* = 20% Standard / 10% Conservative, σ = 20%, μ = 7%, δ = 2.5%, r = 5%. Changed from monthly/quarterly on 2026-07-26; every quoted number moved with it.
- **Moving volatility** (TODO II-40; `drafts/2026-11-22-model-moving-volatility-plan.md`). `Config.vol` — `"constant"` (the default, the code path every present figure comes from, untouched), or the fitted process: `"factors"`, `"jumps"`, `"fitted"` — runs `model.py`'s walk on a lattice of depth × the two volatility factors × the earnings week, whose transitions and per-depth prices `code/lattice.py` simulates once from every volatility node; each put's sale, its week and the lot's first call period are simulated exactly from stationary states, the grid carrying lots from the second period on. `economics()` is shared, and both exact tests hold on the lattice to floating point; the real-world one by channel (the price's and the volatility's) to 0.001bp. Only the running example's rhythm (weekly put, n = 4) is built. The closed forms, the sweeps and §11's static barrier stay constant-σ — the simplified model that explains the mechanism — and §11 says so where it quotes them. σ̄, the scale at which the fitted process's total variance averages σ², is measured by `fairprice.moments` and shared by the lattice and the simulator.
- **Central results.** Mean holding time 2.1y against an 8-week median, because holding time is a first-passage time; the call-grid tax β·σ·√τ_c exceeds the typical entry depth by 2.1× (the ratio goes as √n, so it never vanishes while calls outrun puts); equilibrium inventory is approached over ~90 years, so quoted numbers are finite-horizon; at fair option prices the wheel earns what the stock does on the exposure it carries — its delta, each option's averaged over its life, 93% of its capital at 30y — less the withholding, so it trails the same capital held in the stock by about 0.1 points, exactly the exposure its calls sell; its only edge is the volatility risk premium (every point of spread is worth ~45bp of excess return, break-even against the stock ≈ 0.25 vol points); **two** stability boundaries — lots return iff μ − δ > σ²/2, their capital returns iff μ − δ > σ².
- **Accounting.** The headline "true excess return" uses the economic ledger: inventory at market value, the mark loss booked at acquisition, the upside surrendered booked at call-away — in **dollars per period**, each exit measured against the price its option was sold at, not the price at exit (TODO II-34; the exit price read ~0.2 points high). Every flow is booked on the day it happens, and the account's cash earns r from the day it arrives — the put's collateral, and each premium until its option expires — in both ledgers alike (TODO II-35; before it a window's open calls counted premium and no cost, and the cash earned nothing). The Track A cash-on-cost-basis view is reported beside it as what a brokerage statement shows. The economic ledger is the one that satisfies no-arbitrage — which is used as a test, see below.

## Cautions

- **Sign errors have happened before** (both d₂ and the q formula had inverted signs in early drafts; an early P&L formula double-counted the put premium; the first economic ledger omitted the call-away giveaway). The defense is `code/verify_examples.py` — keep it in sync with the text and re-run after any formula change. It is organized section by section, and `--full` adds the slow far-grid figures.
- **The strongest available test is free**: run the model at m = r − δ and the economic excess return must equal minus the dividend-withholding leak, because nothing beats the risk-free rate under the pricing measure. Its real-world twin: at m = μ − δ the excess must equal the book's delta — each option's averaged over its life (`model.book_delta_life`), not taken at sale — times μ − r, less the same leak, Black–Scholes's result that an instrument earns its delta times the stock's. Both hold exactly at every horizon, and `verify_examples.py` checks them at 1, 5, 10 and 30 years in both regimes to 0.01bp. They have caught four real omissions: the call-away giveaway, exits measured at the exit price (15bp, TODO II-34), and a window's open calls counted without their cost and the account's cash credited nothing (43bp at one year, TODO II-35). Any change that breaks them is wrong.
- **A long-run growth rate is the log of an expectation, not an average of logs.** §10's capital boundary under moving volatility is (1/T) log E~[exp Σ K(H_t)] along the tilted path — the Markov additive process's eigenvalue, `model.vol_boundaries` — and the time-average of K along that path sits below it by Jensen's term, 0.06–0.07 points at the running example; `fairprice.boundaries` reported the time-average as c2 until 2026-11-22. The lots' boundary is a mean drift, and there no such term arises.
- **Stationary means can be pathological.** Expected capital is finite only when μ − δ > σ², and even then it is carried by depths reached over centuries. Quote finite-horizon figures (5/10/30y); use stationary values only to characterize a regime.
- **Grid resolution is not a free parameter.** What matters is h relative to one period's step σ·√τ_c: the near grid Richardson-extrapolates h = 0.01 and 0.005, because a single h = 0.01 grid starts every lot on cells as wide as its entry depth and read Part II's two-decimal figures high (TODO II-32: 11.40 lots for 11.33; `mc_holding.py --window` is the grid-free check), and stationary figures go through `model.stationary()`, which extrapolates two grids because a single one biases E[T] upward by O(h²) accumulated over the tail. §10's moving-volatility boundaries likewise: `lattice.long_run` extrapolates h_slow 0.05 and 0.025, since a single spacing read c2 0.014 points high. `code/mc_holding.py` is the grid-free Monte Carlo that proves it. Never quote a stationary figure straight from `occupation()`. **Those defaults are sized for the running example, and off it the period cap truncates before h does** (found by II-7, 2026-07-29): the survival sum's geometric closure is exact only once the walk has settled into its slowest mode, which takes ~σ²/ν² years — 64 at the running example against 2,300 at σ = 28%, where the default 8000 periods read E[I] = 106 against 129. Any stationary figure at parameters other than the article's must go through `stationary_converged()`, which doubles the cap and reports what it could not converge as a lower bound. Related trap: ν = 0 arrives as **+7e-18**, not 0, so a grid rule of the form 8/θ asks for 4e18 cells — `_sweep_cell` refuses cells that flat rather than approximating them.
- `code/model.py` is the analytic core and the single source of formulas; nothing else may define one. `code/wheel_sim.py` is the independent Monte Carlo check on it — deliberately sharing no machinery, so agreement is evidence — and `--scenario validate` is that comparison, component by component. `--scenario constrained` is the finite account: it is the *only* source of a liquidation probability, because `model.py`'s barrier is static (book frozen, price moving) and a running account's is not. Its defaults are the unlimited operator, so the other scenarios are byte-identical with the ledger present; check that with a diff after touching `run_path`. The scaffolding of the superseded homogeneous model was deleted on 2026-07-28; if you need to see it, it is in git history, not on disk.
- **Performance, and dependencies.** The computation is stdlib plus one optional accelerator: `model.py` uses `numpy.convolve` for the depth walk when numpy is importable, falling back to the original Python loop when it is not. The stdlib-only rule was lifted on 2026-09-15 for figures, which need **matplotlib** — imported only when a figure is drawn, so every example still runs, checks and prints without it, and `verify_examples.py` reports the figure-drift check as skipped rather than failing when it is absent. The volatility calibration of II-40's plan — `code/volstats.py`, `code/jumps.py`, `code/volfit.py` — **requires numpy** outright (agreed 2026-11-21): a fit is thousands of evaluations, each eight simulations of the universe, and has no plain-Python path. `volfit.py` runs its replicas in worker processes of its own, one per replica so each keeps its fixed draws, and honours `WHEEL_WORKERS=1` the same way. Its earnings dates come from `code/earnings.py`, whose EDGAR fetches need a contact in `WHEEL_EDGAR_CONTACT` only when its cache under `data/aristocrats/` is missing something; `code/earnmoves.py` fits the earnings law on them. The fitted result is pinned in `code/volprocess.py` (stdlib), which `wheel_sim.py --scenario fittedvol` steps a session at a time; that scenario's fair-price tables come from `code/fairprice.py`, **built with numpy** (about eight minutes per parameter set) and cached under `data/fair/`, keyed by everything they depend on, so every other scenario stays stdlib. Build them in the parent before a pool runs (`wheel_sim.fitted_parts`), or every worker builds the same tables at once. `code/lattice.py`, behind `Config.vol`, **requires numpy** and caches under `data/lattice/` in three layers keyed by everything they depend on: the tables (10–15 minutes per parameter set at the fitted process, seconds with the volatility held still), the exact entry (2–4 minutes, so a change to it does not rebuild the tables), and each walk once run (a 30-year walk about six minutes; the stationary pair, 4,000 periods on two grids, about an hour). `verify_examples.py` reads the lattices from the cache and reports its moving-volatility checks as skipped where one is missing. Any script that builds one runs pools, so on Windows its top-level code must sit under `if __name__ == "__main__":` — without it every spawned worker re-runs the script and the pool breaks ("A process in the process pool was terminated abruptly"). In `model.py`, keep both numpy paths working — `verify_examples.py` has a structural check that they agree, and if you edit `DepthWalk.step()` you must edit both. Sweeps run through `model.pmap()`, a `ProcessPoolExecutor` wrapper: worker functions must be module-level and their arguments picklable, and `pmap` is only ever called from top-level code, never from inside a job. `WHEEL_WORKERS=1` forces serial execution — use it when debugging, and diff parallel against serial output after touching a sweep.
